# Pixiv 来张图（标签检索）

> 这是「标签检索」变体：取图流程与原版一致，区别是**设了最低收藏数时会优先走 Pixiv 的「N users入り」约定标签**去捞攒够收藏的作品。两个技能共用同一份 PID 索引与图库（都在数据目录的 `pixiv/` 下），所以同一张作品不会被两个技能各发一次。

群友说「**来张 恋恋**」，机器人就从 Pixiv 找一张符合角色标签的插画发进群，并附上标题、作者、收藏量。

和常见的「关键词搜图」不同，这个技能是**按角色标签**搜 Pixiv 插画的，而且**记得自己爬过什么**——同一个作品不会被反复发出来。

---

## 它解决什么问题

大多数搜图机器人的通病是：搜到的图翻来覆去就那几张，因为每次都是从搜索结果里随机挑，没有任何"发过什么"的记忆。爬几次把候选耗尽之后，还会直接报"没找到图"。

这个技能把「爬过什么」记成一份 **PID 索引**：

- 挑选候选**之前**就按作品 ID 把爬过的剔掉 —— 保证每次给的尽量是新图
- 新图真的翻完了，会明说「这些是以前存过的」并复用本地文件，**而不是报失败**
- 索引里连作者、标题、收藏量一起存了，以后回答"这张谁画的"不用再联网

## 特性

| 特性 | 说明 |
|---|---|
| **PID 索引去重** | 原子写盘的 `pid-index.json`，O(1) 查询。断电不会毁掉整个索引 |
| **迁移友好** | 目录扫描兜底：从别的机器人搬过来的图库，靠文件名 hash 后缀也能识别为"已入库" |
| **附带作品信息** | 发图后补一条：标题、作者、收藏/点赞/浏览、作品号。可关 |
| **标签词典自学习** | 模型填一次日文标签就永久记住，下次零成本；也支持导入你既有的中→日映射表 |
| **代理保活** | 端口没开时可自动后台拉起 sing-box 核心（默认关），带 60 秒节流和并发锁 |
| **热度阶梯下调** | 当前档没有没发过的新图，就按 100 收藏一档自动下调（最低 100users入り）；档位按词条记进 tag-floor.json，下次沿用；绝不重发已发过的图 |
| **代理不可用早报错** | 区分"代理没开"和"搜索失败"，给出可执行的提示 |

## 装之前你需要知道

1. **必须能访问 Pixiv**。国内需要自备代理，本技能不提供节点。默认按 v2rayN 的常见配置 `socks5h://127.0.0.1:10808` 预设，可在设置里改。
2. **依赖 `curl.exe`**。Windows 10 1803 及以上系统自带，无需安装。
   （为什么不用内置的网络请求：Node 的 undici 不支持 socks5 代理，而 Pixiv 场景基本必须走 socks5。）
3. **需要一个能看图、能写信的模型**——不需要视觉能力，本技能不分析图片内容，只按标签搜索。

## 使用

对机器人说下面任意一句（群里需要 @ 它）：

```
来张 古明地恋
来一张 博丽灵梦
给我来张 琪露诺
找张 芙兰朵露
```

**日文标签由模型自动补全**。模型认识东方角色，会在调用时一并给出该角色的 Pixiv 日文标签（例如 古明地恋 → 古明地こいし），技能把这个映射记进词典，之后同一个角色就是零成本。你也可以在设置里导入已有的映射表。

一次最多发 3 张（`count` 参数）。

**发哪张**（v1.1.4 起）：默认优先发**最新**的达标作品（按投稿时间从新到旧，同刻收藏高的优先）；调用方传 `hot: true`（用户明确要「高收藏/热门/经典」）时，改按收藏+点赞加权随机挑。两种方式都只从"没发过"的达标新图里挑。

**多标签组合搜图**（v1.1.5 起）：想要「某角色的壁纸/头像/表情包」这类按主题找图时，把筛选词翻成日文填进 `extraTags`（壁纸→壁紙、头像→アイコン、表情包→リアクション画像），工具把角色日文标签与筛选标签 AND 在一起检索；多词组合不会写入角色标签词典，正常搜角色图的档位记忆也不受影响。

## 设置项

| 设置 | 默认 | 说明 |
|---|---|---|
| `apiBase` | `https://www.pixiv.net` | 接口域名，换镜像站时改 |
| `proxy` | `socks5h://127.0.0.1:10808` | 代理地址，留空 = 直连 |
| `autoStartProxy` | 关 | 端口没开时后台静默拉起 sing-box |
| `proxyCoreDir` | 空 | v2rayN 目录（仅自动拉起时需要） |
| `legacyTagDict` | 空 | 外部的「中文→日文 tag」映射表路径，首次运行导入 |
| `imageDir` | 空 | 图库目录。留空 = 存在程序数据目录下，随数据备份 |
| `showInfo` | 开 | 发图后附带作品信息 |
| `minBookmarks` | 1000 | 最低收藏数，0 = 不限。设了门槛就优先用「N users入り」约定标签检索，再按真实收藏数复核 |
| `strictMinBookmarks` | 关 | **v1.1.0 新增，v1.1.3 语义更新**。关：当前档没有没发过的新图时自动下调收藏档（每次 100，最低 100 收藏）；开：不允许下调，没找到达标新图就直接说明，不发图 |
| `usePopularTag` | 开 | **v1.1.0 新增**。用 Pixiv 的「N users入り」约定标签找高收藏作品，不够时自动回落到普通标签 |
| `candidatePages` | 3 | 搜索翻页数，**1~10**（v1.1.0 起上限从 3 放宽）。设了收藏门槛时它才真正起作用 |
| `skipMultiPage` | 开 | 只爬单张插图，排除多页图集 |
| `mode` | `safe` | `safe` 全年龄 / `all` 含 R18 |
| `type` | `artwork` | `artwork` 只插画 / `all` 含漫画 |
| `timeoutMs` | 25000 | 单次 Pixiv 请求超时（毫秒） |

## 数据存在哪

都放在 QQ Agent 数据目录的 `pixiv/` 子目录下：

```
pixiv/
  pid-index.json    爬过的作品索引 {pid: {file, folder, tags, author, title, ...}}
  tag-dict.json     中/英 → 日文标签映射
  tag-floor.json    每个词条当前用到的热度档位（避免每次都从设定值重新下调）
  images/<角色>/    下载的图片（imageDir 留空时）
```

删掉 `pid-index.json` 相当于"忘记爬过什么"，之后会重新爬重复的图。

## 已知的限制

- **图集只取一页**。开启 `skipMultiPage` 时直接跳过图集；关闭时随机抽一页，抽到的那页未必符合搜索标签。
- **标签命中率取决于模型给的对不对**。给错了日文标签就搜不到，此时换个说法或手动指定标签。
- **不分析图片内容**。它只按标签搜，不判断图里画的是不是你要的角色。
- **`curl.exe` 版本过老可能影响 TLS**。Windows 自带的 7.55 实测可用；如果报 TLS 相关错误，考虑装新版 curl。
- **「users入り」标签靠上传者自觉**。它只是 Pixiv 上的民间约定，偶尔有人乱打，所以最终仍会按真实收藏数复核；门槛设得越高，越可能"翻遍候选也没有达标的"。

## 更新记录

### v1.1.7 —— 角色名自动解析成日文标签（不再依赖模型瞎猜）

**修的问题**：模型不知道角色的日文标签时，会去外部搜索工具查——常查到**游戏/作品名**（如 アークナイツ、原神），然后拿去当 `tag`，搜出来的是该作品**所有角色**的混图，和群友点名的角色不符。

**改动**：

- **工具自带标签解析**：模型不给 tag 时，用 Pixiv 搜索框同款的联想接口（`/ajax/search/tags/{词}`）把中文角色名解析成官方日文标签——Pixiv 的 pixpedia 词典里写着「芙宁娜：『原神』の登場人物「フリーナ」の中国名」，parentTag 就是正确答案；解析成功自动学进词典，下次零成本；
- **防误判**：只在摘要明确声明"查询词是 parentTag 的别名"时采信（如「フリーナ」の中国名、「初音ミク」の正式な漢字表記），不会把原神/アークナイツ这类作品分类词解析出来；解析不出就退回原名硬搜；
- **引导收紧**：工具描述与调用指引明确——tag 必须是角色**本人**的日文标签，不要拿游戏/作品名当 tag；作品/游戏名适合填 extraTags 区分同名角色。

### v1.1.6 —— 明确要求配话走 send_message

**修的问题**：工具只说"配一句短话"，模型有时把短话直接写在回复文本里——而模型的普通回复不会出现在 QQ 里，群里只看到图没有话。现在成功/失败的工具结果都带明确提示（成功：短话必须调用 send_message 发到当前会话；失败：用 send_message 简短告知群友），skill 调用指引同步强调。

### v1.1.5 —— 支持多标签 AND 检索（壁纸等主题找图）

**改动**：新增 `extraTags` 参数：附加筛选标签（空格分隔多个），与角色日文标签 AND 组合检索。模型引导里给出常用翻译（壁纸→壁紙、头像→アイコン、表情包→リアクション画像），用户说「来张 XX 的壁纸」时模型会带上 `extraTags: "壁紙"` 调用。配套调整：

- `tag` 仍接受空格分隔的多标签；但**含空格的组合词不再写入角色标签词典**，避免把「初音ミク 壁紙」存成角色映射污染后续搜索；
- 档位持久化的 key 从"角色标签"改为"角色标签＋附加标签"——同一角色的普通图和壁纸图降档记忆互不干扰；
- 消息与日志里的词条显示改为「初音ミク＋壁紙」形式，一眼看出本次的检索组合。

### v1.1.4 —— 默认优先发最新的图

**改动**：挑选策略从"收藏+点赞加权随机"改为**默认按投稿时间从新到旧，取最新的达标作品**（同刻投稿的按收藏高的优先）。用户明确要「高收藏/热门/经典」时，调用方传 `hot: true`，保留原来的加权随机挑选。两种方式都只从"没发过"的达标新图里挑，热度阶梯下调与档位持久化逻辑不变。

### v1.1.3 —— 去掉复用降级，改为热度阶梯下调（按词条记忆）

**修的问题**：同一个标签用几次之后，机器人开始重复发以前发过的图。原因有两层：

1. 旧设计里有「候选耗尽降级」：搜到的候选全发过时，从已发图里按收藏数加权再挑一张补数，并在结果里标注「[复用已存的]」。冷门标签候选池小，几次就耗干——于是反复发同一张最热门的，观感很差；
2. 每次都从设定的最高档（如 1000users入り）重新搜起，明明上次已经降过档，白搜一通。

**改动**：

- **绝不重发**：发过的作品（PID 索引）在搜索阶段就被剔除，选图只从"没发过"的新图里挑，任何情况下不会把同一张作品发第二遍；
- **热度阶梯下调**：当前档凑不齐没发过的新图 → 下调 100 收藏一档（1000users入り → 900users入り → …），最低 100users入り，最后用普通检索兜底；已搜到的候选跨档共享（不重复拉详情），详情请求总量有上限（240），防止深降档时请求失控；
- **档位按词条持久化**：实际发图用到的档位记进 `tag-floor.json`（发图成功才记录），下次直接从记住的档位开始；每次仍会先复查一次最高档（设定值档），有新热门图就自动把档位升回去；
- **严格门槛语义更新**：`strictMinBookmarks` 开 = 不允许下调，没找到达标新图就直接说明，不发图；
- 没有可发新图时明确说明（搜到的都发过 / 降到底也没达标），不再静默用旧图顶数。

### v1.1.2 —— 网络层弃用 curl.exe，改为纯 Node 实现

**为什么换**：修复「没搜到」（v1.1.1）后，真实错误终于能透出来了，随即暴露出下一层问题——**这台机器上 curl.exe+Schannel 不可靠**：同一代理下，Node(OpenSSL) 的请求全部正常，而 curl 的 TLS 握手时而报 `curl: (35) Recv failure: Connection was reset`（实测日志）。QQ Agent 本体走 Node 不受影响，只有技能的 curl 踩坑。

**改动**：

- 搜索、详情、图片下载全部改用纯 Node 实现：http/https 代理走 CONNECT 隧道；socks5/socks5h 自带 SOCKS5 握手（socks5h = 域名交给代理远端解析，国内必需语义不变）；直连走普通 TLS；跟随 3 跳重定向；下载失败会写日志（之前是静默吞掉）。
- 不再依赖 `curl.exe`：去掉「Windows 10 1803+」「旧版 curl TLS 兼容性」两条限制。
- 超时语义：连接阶段 15s 封顶，整体响应 `timeoutMs`，与原行为一致。

**验证**（真实配置、真实网络）：搜索「初音ミク 1000users入り」→ 55 个候选 → 选中收藏 1107 的作品 → 图片成功下载落盘 → 消息附带标题/作者/收藏，全链路 14s。

### v1.1.1 —— 修复「不管搜什么都提示没搜到」

**现象**：代理配置正确、端口也在监听，但任何关键词都返回「没搜到『xx』的图」，数据目录里连 `pid-index.json` 都建不起来（一张图都没发出去过）。

**根因**（用同一代理实测 Pixiv 接口定位）：

1. 搜索请求写死 `type=artwork` 去请求 `/ajax/search/illustrations` 端点。Pixiv 对这个组合**一律返回 HTTP 400「不正确的请求」**（实测换请求头、换 mode、换 s_mode、去掉参数都一样，只有换 type 或换端点才行）。
2. 更隐蔽的是：这个 400 的响应体恰好是**合法 JSON**——`{"error":true,"message":"不正确的请求。","body":[]}`。旧代码 `JSON.parse` 能解析成功，但 `body.illust.data` 取不到 → 静默变空数组 → 被报成「没搜到」。网络层失败也一样被 `catch { return [] }` 吞掉，所以日志里什么都没有。

**修复**：

- 按设置的「作品类型」映射到实测可用的组合：`artwork`（只插画）→ `illustrations` 端点 + `type=illust_and_ugoira`；`all`（含漫画）→ `artworks` 端点 + `type=artwork`。
- 搜索的真实错误不再吞成空结果：curl 失败（带退出码和 stderr）、返回非 JSON、Pixiv error JSON，都会带着原始原因报出来。
- 翻页中途的偶发失败只记日志、用已拿到的候选继续（一页都没拿到才整体报错）。

**验证**（同一代理下实测）：修正后普通标签与「1000users入り」检索均返回 60 条/页，详情接口正常返回收藏数，`i.pximg.net` 图片下载返回真 JPEG。

### v1.1.0 —— 让「最低收藏数」真正生效

修的是"设了收藏门槛、却照发低收藏作品"的问题。原因有三层，前两层是代码里的坑，第三层是 Pixiv 自己的限制：

1. **候选池写死 24 个**：只取搜索结果里最新的 24 个作品去比收藏，于是「搜索翻页数」调到 5 也毫无作用（第 1 页就填满了）。→ 现在候选上限跟随翻页数（最多 120 个），并且"达标候选够挑了"就提前收工，不会无脑翻到底。
2. **翻页数被静默夹到 3**：`Math.min(3, ...)`，填 5 实际按 3 跑。→ 上限放宽到 10。
3. **Pixiv 搜索接口在未登录时只提供"最新优先"**：`order=popular_d`（按热度）与 `blt`（收藏数筛选）参数**会被直接忽略**（实测五种写法返回同一批结果），所以"最新的一两百个作品"收藏根本还没攒起来——实测翻 5 页 142 个候选，最高只有 444。→ 改用上传者自己打的**「N users入り」约定标签**（实测「初音ミク 500users入り」前 5 个作品收藏 754 / 881 / 775 / 531 / 839，「1000users入り」前 5 个 5818 / 1263 / 1331 / 1860 / 1023），设了门槛就优先走这条路，不够再回落普通标签。

另外：**一旦放宽门槛，会在群消息、工具结果和日志里同时标注**，不再静默发出低于门槛的图。（旧实现的设置说明里确实写了"会自动放宽"，但没人会在用之前去读那一行。）
